## 命名规范

- 机制设计文档（讲清某项机制的设计与现状，供维护者理解）：`<主题>-design.md`
- 实施指南文档（给实施 agent 的分步操作文档，含代码锚点与验证清单）：`<主题>-guide.md`
- `<主题>` 用小写英文短横线分词，与文档 H1 标题对应

## 内容格式规范

1. **H1 标题**：`GFS <主题>机制设计` / `GFS <主题>实施指南`。
2. **头部元信息**（紧跟 H1 的 `>` 引用块，字段顺序固定，块后空一行接 `---`，正文不再使用分隔线）：
   - 机制设计：`> 面向维护者：<一句话覆盖范围>` + `> 最后更新：<YYYY-MM-DD> —— <本次变更摘要>`
   - 实施指南：`> 目标读者：<负责实施编码的 agent>：<用法>` + `> 代码基线：<YYYY-MM-DD>，commit <hash>（`文件:行号` 锚点漂移以符号搜索为准）` + `> 执行约束：<可选>` + `> 最后更新：<YYYY-MM-DD> —— <本次变更摘要>`
3. **章节编号**：正文从 `## 1.` 起连续编号，小节 `### N.M`；实施指南允许 `## 0.` 承载项目约定。
4. **表格**：表头分隔行统一为 `| --- |`。
5. **语言**：中文；代码块标注语言；时序/结构图用 ASCII 围栏代码块。
6. **推荐骨架**（不强制追溯，新增文档遵循）：
   - 机制设计：设计定位 → 组件全景 → 数据模型 → 核心链路（时序）→ 安全与边界 → 接口/配置清单 → 扩展与维护 → 关键文件索引
   - 实施指南：背景与已定决策 → 代码现状 → 总体架构 → 分阶段实施步骤 → 验证与验收 → 附录
